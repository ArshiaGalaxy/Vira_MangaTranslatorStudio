def submit_job(project, kind, func): with _lock: if project.id in _running: raise JobAlreadyRunning() job = Job.objects.create( project=project, kind=kind, status="queued") _running[project.id] = job.id Thread( target=_run, args=(job.id, project.id, func), daemon=True, ).start() return job def _run(job_id, project_id, func): try: mark_running(job_id) result = func() # مرحله واقعی mark_done(job_id, result) except Cancelled: mark_cancelled(job_id) except Exception as e: mark_failed(job_id, str(e)) finally: _running.pop(project_id, None)
یک وظیفه فعال برای هر پروژه

جلوگیری از دو رندر هم‌زمان روی یک پوشه؛ درخواست دوم صریحاً رد می‌شود، نه اینکه صف بی‌پایان بسازد.

تلاش مجدد برای قفل SQLite

نوشتن‌های کوتاه با transaction.atomic و retry کوتاه؛ خطای database is locked مدیریت می‌شود.

لغو مشارکتی

لغو، thread را نمی‌کُشد؛ بین مراحل یک پرچم بررسی می‌شود تا فایل‌ها نیمه‌کاره نمانند.

محافظ وضعیت نهایی + zombie healing

وظیفه تمام‌شده دوباره اجرا نمی‌شود؛ در شروع مجدد سرور، وظیفه‌های running قدیمی به failed منتقل می‌شوند.

یک منبع حقیقت

رکوردهای TextBlock و فایل‌های media/projects/ مرجع‌اند. شمارنده‌ها کش UI هستند و بعد از هر تغییر بازمحاسبه می‌شوند.

۳
یک اندازه‌گیری

پیش‌نمایش و رندر نهایی هر دو از resolve_style و text_layout استفاده می‌کنند؛ دوباره‌پیاده‌سازی در JavaScript ممنوع.

مسیر کامل در شش خط
PDF / image → analyze (STANDARD | LONG_STRIP) → OCR (split → detect → dedup → cluster → merge) → persist (TextBlock in page pixels) → translate (batch JSON + context + glossary) → inpaint (mask → backend chain) → render (RTL typography) → export (PDF | ZIP | PSD)
استدلال سراسری، ذخیره‌سازی محلی. OCR کل فصل را می‌بیند، اما ویرایش و رندر در قطعه‌های کوچک انجام می‌شود.
